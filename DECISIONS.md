The design decisions in the build brief are Aidan's and are not repeated here; this log covers
what the brief left open and what was found on the site.

## Site facts (found 2026-10-17)

- **Brand red is `#ED2839`** — it is the Elementor kit's Primary and Accent colour and its saved "SEDS Red" (kit 6414), Astra's theme and link colour (`astra-settings` → `theme-color`, `link-color`, palette slot 0), and the colour used 57 times in the homepage's CSS (header, buttons, links). Change: `--sp-red` at the top of `assets/spellar.css`.
- **Site sans-serif is Source Sans Pro** — Astra's body font (`'Source Sans Pro', sans-serif`) and the Elementor kit's Text/Accent font; the menu uses it at 600. Elementor pages load every weight from `wp-content/uploads/elementor/google-fonts/`; Astra loads weight 400 from Google Fonts on every page. The "SEDS" label uses it and falls back to the system sans. Change: `--sp-sans` in `assets/spellar.css`.
- **WP-CLI needs PHP 8.3 on the server** — the command line defaults to PHP 8.2 and Contact Form 7 refuses to load on it, so every `wp` command that loads WordPress crashes. Every server command and `bin/deploy.sh` sets `WP_CLI_PHP=/usr/local/php83/bin/php`. Change: the `WP_CLI_PHP` line in `bin/deploy.sh` if the site moves to a newer PHP.
- **The "Elementor mobile menu" is the site's own menu bar** — the header is Astra's, restyled by the must-use plugin `seds-nav` (seds-web repo); below 1,100 px its drawer reuses the same `#primary-menu` list, and links that do not fit move under "More" as the same `<li>` elements. So the menu dot only has to find `.spellar-menu-item` once.
- **No SEO plugin is active and the site is public (`blog_public` = 1)** — "SEO noindex left at the site default" therefore means: indexable, nothing set on the page.

## Data

- **Allowed guesses = ENABLE + a SCOWL top-up − two blocklists + every answer** (50,864 words). ENABLE (public domain, [dolph/dictionary @694bf95](https://github.com/dolph/dictionary)) is the base. It lacks about 250 common modern words (EMAIL, ONLINE, AIRLOCK, WEBSITE), so SCOWL size 50 (US/GB/CA, [app.aspell.net](http://app.aspell.net/create), © Kevin Atkinson, permissive licence) fills those in, minus a hand list of abbreviations. Removed: the LDNOOBW English list ([CC BY 4.0](https://github.com/LDNOOBW/List-of-Dirty-Naughty-Obscene-and-Otherwise-Bad-Words), mostly sexual terms) and, from [dsojevic/profanity-list](https://github.com/dsojevic/profanity-list) (MIT), every entry of severity 2+ and every racial or anti-LGBTQ slur, each with its plural and other simple endings. Some blocked words have innocent meanings too (DYKE, PANSY); blocking them as guesses was judged the smaller harm. Change: `bin/build-guesses.mjs`, then re-run it.
- **`words.json` entries carry a fourth field, `"proper": true/false`** — the brief limits proper nouns to 30–40% and to two days in a row, which needs a per-word flag. "Proper" means the fact treats the answer as a name (planet, star, constellation, spacecraft, mission). Change: edit the flag; `validate-data` requires it.
- **Pinned facts must contain "on this day"** — `validate-data` enforces the brief's rule that a pinned fact says why it is on that day.
- **A pinned word appears only on its anniversary** (once a year); the daily rotation draws from the unpinned words. 02-29 cannot be pinned.
- **The schedule's launch date is provisional: 2026-10-17** — puzzle #1 should be the day the page is published. Before publishing, `node bin/extend-schedule.mjs --relaunch <date> --force` renumbers and regenerates it; after publishing that must never be run again.
- **Schedule generated 400 days ahead** (the brief asks for at least 365). `validate-data` fails when fewer than 60 days remain, so a deploy forces an extension.
- **Every dated or numbered fact was checked by web search on 2026-10-17**; sources in `docs/fact-sources.md`, open questions in `docs/word-review.md`.

## Look and layout

- **(Superseded 2026-10-18 by the title swap, below.) Wordmark: variant (a), a red "t" at 45% opacity over a black "p", in Cormorant Garamond 600** — (b) the black t at 25% read as a grey smudge; (c) EB Garamond was heavier and less atlas-like; Playfair's thick t stem looked like a glitch. The t is placed exactly on the p's stem: measured from rendered glyphs, both stems sit the same distance from the glyph's start, so the t starts where the p starts. Placed over the p (not behind it), the p's upper stem turns dark red and a whole red t emerges from it, so "Spellar" reads first and "Stellar" on a second look. Images: `docs/screens/wordmark-*.png`, study sheet `dev/wordmark.html`. Change: `.sp-t` in `assets/spellar.css`.
- **The display font is one weight (600), Basic Latin only, 10.8 KB** — `bin/build-fonts.py` cuts it from Google's variable font (OFL; licence in `assets/fonts/OFL.txt`). Used for the wordmark, the answer label and dialog titles. Change: `SHIP` in the script, then the `@font-face` rule.
- **Tiles, keys, stats and body text use the site's own Source Sans Pro, not a copy of it** — the theme already loads it on every page, so the game adds no font request for it. Falls back to the system sans.
- **All CSS is scoped to the root element by its id (`#spellar-root`, the same element as `.spellar`), and the root starts from `all: initial`** — rules for plain elements from the theme or Elementor (`.elementor-kit-6414 button`, `h2` ...) would otherwise tie with or beat class-only selectors; an id prefix outranks them all and nothing inherited leaks in. Change: the prefix throughout `assets/spellar.css`.
- **Tile size follows a height budget that includes the site's header** (64 px on phones, 76 px from 1,100 px; it scrolls away but is on screen at first): on a 360×640 phone the whole game, wordmark to keyboard, fits below the header with 41 px tiles. Change: `--sp-above` and `--sp-chrome` in `assets/spellar.css`.
- **Contrast** — white on SEDS red is 4.2:1, so key letters are 19 px bold (WCAG "large text", needing 3:1) and tile letters are larger still. Grey letters on the grey "not in word" fill (#5E5E5E on #DCDCDC) are 4.7:1. The red "SEDS" is part of the logotype, which WCAG exempts.
- **No icons anywhere**: the delete key says "Delete", dialogs close with a "Close" button, and the stats open from a text button.
- **Guess distribution: outlined bars, today's bar filled black** — red is kept for letter states and stars only.
- **Results appear in place of the keyboard** once the game ends (answer label, fact, stats, Share, countdown); the footer's Stats button opens the same numbers in a dialog at any time. While reviewing the board at full strength the constellation is hidden, since stars sit on the letters.
- **When the countdown reaches midnight the page reloads** to bring in the next puzzle; a game still in progress at midnight is left alone.

## Behaviour

- **The fact is obfuscated in the API response too, not only the answer** — most facts contain the answer word, so a readable fact in the network tab would spoil the puzzle as surely as the answer. Same XOR-and-base64 shield, same field names.
- **The puzzle is requested as early as possible and kept for the day** — a WordPress REST request takes about 2.5 s on this host. A tiny inline script printed after the root element starts the request while the page is still loading, and the response is saved with the game state, so a return visit the same day renders at once with no request. Change: `assets/early.js`. (Since 2026-10-18 the page itself carries the puzzle and this request is only the fallback for an old saved copy; see below.)
- **The guess list is a plain text file the browser downloads once** (`data/guesses.txt`, 363 KB, about 122 KB gzipped, cached by the browser), fetched while the player thinks about the first guess. Checking guesses on the server would cost a 2.5 s WordPress request per guess.
- **"Played today" (which hides the menu dot) means today's puzzle was finished** — a started but unfinished game keeps the reminder.
- **No menu dot when browser storage is blocked** — the script cannot tell a new visitor from a regular, and a dot that never goes away would be worse than none.
- **On phones (coarse pointer) Share uses the system share sheet; elsewhere it copies** and shows "Copied", as the brief asks.
- **Event dates**: start, finish and share are counted on the puzzle's date (so a row of the stats table is one puzzle); Français clicks on the server's UTC date.

## Motion

- **Timings are the brief's starting values, unchanged after review** (the reveal was replaced on 2026-10-18, below) — all in one table at the top of `src/motion.js` (`T`). Review notes: `docs/motion-review.md`.
- **The toast sits above the board**, over the tagline, so it never covers the row being guessed (it did, in the first review pass).
- **When the game ends the keyboard and legend go at once**, leaving the board alone for the constellation; the results set in below it. No extra animation, since the brief allows only the four moments.
- **Typing during a reveal is ignored**, as the brief requires (input locks); the board carries `aria-busy` meanwhile.
- **A tap anywhere on the page, or any key, skips the end sequence.**
- **Without GSAP (blocked script) the game still works**, with the reduced-motion behaviour.

## Server (plugin)

- **Assets are enqueued when the page's content or its Elementor data contains `[spellar`**, in `<head>` (CSS, font preload, and since 2026-10-18 the game's script, async) and deferred in the footer (GSAP, DrawSVG); the shortcode also enqueues as a fallback. Versions are file modification times, so a deploy changes every URL. Change: `spellar_page_has_game()` in `spellar.php`.
- **Script handles are prefixed (`spellar-gsap`, `spellar-drawsvg`)** so they cannot collide with another plugin's "gsap".
- **The game's script and style tags carry `data-wpacu-skip="1"`** — the site's Asset CleanUp has "combine JS" on. At first it merged the three game scripts into one deferred file correctly, but after a deploy changed `spellar.js`'s version, the cached page came out with the GSAP and DrawSVG tags missing (the game still worked, without animation). The attribute is Asset CleanUp's own opt-out ("do not alter it"), so its settings stay untouched. Change: `spellar_skip_combining()` in `spellar.php`.
- **`data/*.json` is denied to browsers** by `data/.htaccess` (Apache) — otherwise the whole schedule, every future answer, could be downloaded from the plugin folder. `guesses.txt` stays public. `index.php` files stop directory listings. (The GitHub repository is public, so the schedule is readable there anyway; see the report.)
- **Every refusal from the puzzle route carries `Cache-Control: no-store`**; the `date` parameter is validated in the callback rather than by WordPress's argument check for that reason.
- **A server error (503) is returned if `data/` is missing or unreadable**, rather than a broken puzzle.
- **Fallback dates are remembered** in the option `spellar_fallback_dates` (one write per date, last 30 kept); the admin notice and `wp spellar stats` warn about any in the last 7 days, and about a schedule with under 60 days left.
- **The rate-limit transient name is `spellar_rl_` + 24 hex characters of an HMAC (SHA-256, keyed with WordPress's `nonce` salt) of the address and the UTC date**; it expires at the end of the UTC day. 20 events a day.
- **The table's primary key is (date, metric)** — that is the unique key the brief asks for. `admin_init` recreates the table if its version option is missing (for example after restoring an older database).
- **WP-CLI: `wp spellar stats [--days=30] [--format=table|csv|json]`, `wp spellar schedule`, `wp spellar flush-page`** (the last clears WP Super Cache's copies of /spellar/ after a deploy, with the cache plugin's own `wpsc_delete_url_cache()`).
- **Deploy goes over SSH as a tar stream** (this Windows machine has no rsync); the server checks every PHP file with `php -l` (PHP 8.3, the site's version) before its own `rsync --delete` mirrors the files into the plugin folder. Only `spellar.php`, `uninstall.php`, `includes/`, `assets/`, `data/` ship.
- **Tested in WordPress Playground** (WordPress 7.1, PHP 8.3, SQLite): the PHP and JavaScript puzzle logic return identical responses; dates ±1 day accepted, ±2 and malformed refused; events validated before the rate limit; the 21st event of a day refused; the table kept on deactivation and dropped on uninstall.

## After the first play-through (2026-10-18)

Aidan played the live game on a phone and a PC and asked for these changes; they override the
brief where they differ from it.

- **Why the first visit took over 5 s** (measured with `node dev/perf.mjs`, a first-time visitor, analytics intercepted): the page itself arrives from the page cache in ~0.25 s, but the board waited for `GET /puzzle`, which boots WordPress: 4.2 s on a throttled phone run (board at 5.3 s), 5.7 s on a desktop run (board at 8.8 s). The request also only started once the site's head scripts had run, and it competed with WP Statistics' own WordPress request (4.8 s).
- **The page now carries the puzzles for the server's yesterday, today and tomorrow (UTC)** in the root's `data-days`, the same JSON the puzzle route gives for those dates (it serves them anyway, so nothing more is exposed). Every time zone's date is one of the three while the saved page is under 10 hours old; WP Super Cache keeps copies 8 hours and checks for expired ones hourly (`cache_max_time` 28800, `cache_time_interval` 3600, mod_rewrite mode), so that holds. An older copy lacks the player's date, and the game falls back to the puzzle route as before. Elementor's element cache is off (`elementor_element_cache_ttl` = disable), so the shortcode's output is fresh on every render. Change: `spellar_page_days()` in `includes/rest.php`; the JS twin is `pageDays()` in `bin/lib/puzzle.mjs`.
- **The game's script loads async from `<head>`** and starts the game as soon as it arrives, instead of deferred, which waits for the whole 330 KB page. If it arrives before the parser reaches the root, the inline script printed after the root starts it (`window.spellarBoot`). GSAP and DrawSVG stay deferred: the game needs them only for animations, which start after a key press, and skips any asked for before they load. Change: `spellar_enqueue_assets()` in `spellar.php`, `src/main.js`, `assets/early.js`.
- **The menu dot is drawn from `<head>`** — the script used to run at the end of the page and add an element, so on a phone the dot appeared ~0.4 s after the menu (more on a slow connection) and nudged the links after it. It now runs in `<head>` and adds a style rule (`.spellar-menu-item>a::after`), so the dot is there when the menu is first drawn and when the menu bar's script measures it. Checked against the live Events page with the new script swapped in (in a test browser only): identical item positions and the same links in the bar at 1280 and 1440 px, and pixel-identical close-ups in the bar and the phone drawer. The script is 593 bytes minified. Change: `assets/menu-dot.js`; the game removes the rule (`#spellar-dot-style`) when the puzzle is finished.
- **Wider screens get more room around the wordmark** — on a PC the phone layout looked cramped. From 600 px wide, the height left over with 56 px tiles on the day's board (`--sp-room`, 0 to 160 px) goes 20% above the wordmark, 15% to a larger wordmark (44 px → up to 68 px), 7% to the tagline and its gap, and 15% above the board; the tiles stay at 56 px and the board and keyboard still fit the first screen. With no room to spare (phones, short laptop screens) nothing changes: checked pixel for pixel against the previous version at 360×640, 375×667, 390×844, 412×915, 844×390 and 1366×657 (only the removed red t differs). The footer of the site may now start below the first screen, which Aidan said is fine. Change: `--sp-room` and the `.sp-head`, `.sp-mark`, `.sp-tagline`, `.sp-play` rules in `assets/spellar.css`.
- **The title swap replaces the p/t overlay** — the overlay did not work in practice. The title reads "Spellar"; 5 s after the page opens, and then every 25–45 s while the page is in view, the p fades out as a black t fades in and the slot narrows from the p's width (0.512 em) to the t's (0.337 em), so "Stellar" closes up like a word set that way; it holds 1.6 s and turns back. Never with reduced motion. Screen readers always hear "SEDS Spellar". This is a fifth moving thing, beyond the brief's four, at Aidan's request. Frames: `docs/screens/motion-title-*.png`. Change: `titleSwaps` and `buildTitleSwap` in `src/motion.js`, timings `swap*` in `T`.
- **The star reveal replaces the scan line** — at Aidan's request (the brief's scan line is gone). Left to right, 150 ms apart, a copy of each tile in its new state grows over it from the centre, clipped to a five-pointed star (inner radius 40% of the outer) that turns from −36° to upright and grows until it covers the tile (420 ms, power2.in, so it reads as a star while it is small); then the tile takes its state. A wrong-spot tile is white in the middle, which hid the star, so its copy starts fully hatched and opens its white square once the star has filled the tile (160 ms). A 7-letter row takes about 1.5 s. Reduced motion: states change at once, as before. Frames: `docs/screens/motion-reveal-*.png`. Change: `buildReveal` in `src/motion.js`, `.sp-cover` in `assets/spellar.css`.
- **The end-of-game block shows the four numbers but no guess distribution** — the bars repeat what the board above already shows. The distribution, with today's bar marked, stays in the Stats dialog. Change: `distribution: false` in `showFinished()` in `src/game.js`.
- **"Not in word" in the share text is ☆ instead of ·** — in proportional fonts the dot is a quarter of a star's width, so the columns did not line up (seen in Discord). ★ and ☆ are a designed pair, the same width in every font that has them; ✦ is within 2% (measured in Segoe UI Symbol, which draws all three on Windows: 0.833, 0.833 and 0.816 em, against 0.217 em for "·"). None of the three has an emoji form. Change: `GLYPH` in `src/share.js`.
- **How to play ends "A new Spellar every day at midnight."** (no longer "your time").
- **Asset CleanUp and a changed `spellar.js`**: reading its code (`CombineJs.php`), a cached combine list is applied file by file and stops at the first file whose checksum changed, deleting the list; the page rendered then can still carry its old combined file. So after a deploy that changes `spellar.js`, the first render of /spellar/ clears the stale list and may hold an old copy of the game alongside the new one (harmless: whichever starts first marks the root and the other does nothing), and the page cache would keep that render for up to 8 hours. The deploy therefore requests the page once and clears its saved copy again (`bin/deploy.sh`), so the copy that stays is rendered from a fresh list, which leaves the game's tags alone (`data-wpacu-skip`).

- **A guess sent before the word list has loaded now marks the board busy while it waits** — found by the live tests right after the speed-up: the board is now ready before the 120 KB word list arrives (it waited for the page to go idle, which a busy page may not do for seconds), and a guess sent that early waited with input locked but the board not marked busy, so keys typed meanwhile were silently dropped. The board now carries `aria-busy` from Enter until the row is revealed, and the list is fetched when the page is idle or after 2 s at the latest. Change: `submit()` and the prefetch at the end of `startGame()` in `src/game.js`.
